# Free Markdown Translator 文档处理逻辑分析

## 概述

Free Markdown Translator 是一个智能的 Markdown 文档翻译工具，其核心优势在于能够在翻译内容的同时完美保持 Markdown 格式。本文档详细分析其文档处理的完整流程和关键技术实现。

## 整体架构

```
输入文档 → 预处理 → 节点解析 → 内容分离 → 翻译处理 → 格式重建 → 输出文档
```

## 详细处理流程

### 1. 文件发现与收集阶段

**负责模块**: `MarkdownTranslator.__collect_files_to_translate()`

**处理逻辑**:
- 扫描指定目录，查找配置中定义的文件名（如 README.md、index.md）
- 检查目标语言文件是否已存在，避免重复翻译
- 生成待处理文件列表和对应的目标语言列表

**关键代码路径**:
```python
for src_filename in config.src_filenames:  # ['index', 'README', '_index']
    src_file = Path(folder) / (src_filename + '.md')
    if src_file.exists():
        # 检查目标文件是否存在，生成待翻译语言列表
```

### 2. 预处理阶段

**负责模块**: `MarkdownTranslator.__preprocessing()`

#### 2.1 文件读取
- 以 UTF-8 编码读取源文件
- 按行分割内容为字符串列表

#### 2.2 节点树构建
**负责模块**: `MarkdownTranslator.__generate_nodes()`

**核心思想**: 将 Markdown 文档的每一行转换为特定类型的节点对象，不同节点有不同的翻译策略。

**节点类型分类**:

| 节点类型 | 对应类 | 翻译策略 | 示例 |
|---------|--------|----------|------|
| 透明节点 | `TransparentNode` | 完全不翻译 | 代码块、分隔符、图片 |
| 实体节点 | `SolidNode` | 完全翻译 | 普通段落文本 |
| 标题节点 | `TitleNode` | 翻译标题内容，保留 # 符号 | `# 标题` |
| 键值节点 | `KeyValueNode` | 翻译值部分，保留键 | `title: 文档标题` |
| 键值数组节点 | `KeyValueArrayNode` | 翻译数组元素 | `tags: ["标签1", "标签2"]` |
| 图片链接节点 | `ImageOrLinkNode` | 翻译描述文本，保留链接 | `[描述](链接)` |

**状态机处理**:
```python
is_front_matter = False  # Front Matter 区域标识
is_code_block = False    # 代码块区域标识
is_not_trans = False     # 不翻译区域标识

for line in src_lines:
    if line.strip() == "---":
        is_front_matter = not is_front_matter
    elif line.startswith("```"):
        is_code_block = not is_code_block
    # 根据状态和内容创建对应节点
```

#### 2.3 待翻译内容提取
- 遍历所有节点，提取需要翻译的文本内容
- 移除空行，记录空行位置用于后续恢复
- 统计翻译字符数用于进度显示

#### 2.4 文本分块处理
**负责模块**: `MarkdownTranslator.__handle_chunk()`

**目的**: 避免单次翻译文本过长导致 API 调用失败

**分块策略**:
- 按行累积文本，当长度超过 500 字符时创建一个块
- 每个块内部进一步分离需要翻译和跳过的部分

**内容分离机制**:
使用正则表达式识别需要跳过翻译的内容：
```python
# 跳过的内容类型
skipped_regexs = [
    r"\*\*。?",           # 加粗标记
    r'#+',                # 标题标记  
    r'`[^\u4E00-\u9FFF]*?`',  # 代码片段
    r'\|',                # 表格分隔符
    # ... 更多模式
]
```

### 3. 翻译执行阶段

#### 3.1 多线程调度
**负责模块**: `MarkdownTranslator.__parallel_translate()`

- 创建线程池，默认线程数等于目标语言数
- 为每个文件-语言对创建独立的翻译任务
- 使用全局和局部进度条显示翻译进度

#### 3.2 批量翻译处理
**负责模块**: `Translator.translate_in_batch()`

**处理流程**:
1. 遍历每个文本块
2. 调用 `__translate_with_skipped_chars()` 处理单个块
3. 将翻译结果按原有结构重新组装

#### 3.3 智能内容过滤翻译
**负责模块**: `Translator.__translate_with_skipped_chars()`

**核心机制**:
```python
# 分离需要翻译和跳过的部分
skipped_parts = {}      # 跳过翻译的部分（代码、链接等）
need_translate_parts = {} # 需要翻译的部分

# 只翻译需要翻译的部分
text_to_translate = "\n".join(need_translate_parts.values())
translated_text = self.translate(text_to_translate, src_lang, target_lang)

# 重新组装，保持原有位置关系
total_parts = {**skipped_parts, **need_translate_parts}
return "".join(total_parts[i] for i in range(parts_count))
```

#### 3.4 翻译 API 调用
**负责模块**: `Translator.translate()`

**特性**:
- 支持多种翻译引擎（Google、百度、腾讯等）
- 自动重试机制，最多重试 5 次
- 指数退避策略，重试间隔递增
- 代理支持，适应不同网络环境

### 4. 后处理与格式重建

#### 4.1 翻译结果填充
**负责模块**: `MarkdownTranslator.__translate_lines()`

**处理逻辑**:
- 将翻译后的文本按行分割
- 根据每个节点的 `trans_lines` 属性分配对应的翻译内容
- 处理机器翻译警告占位符的替换

#### 4.2 节点内容重组
**负责模块**: 各节点类的 `compose()` 方法

每种节点类型都有专门的重组逻辑：

```python
# 标题节点重组
class TitleNode:
    def compose(self):
        return self._index + self._signs + " " + self.value + '\n'
        # 输出: "# 翻译后的标题"

# 键值节点重组  
class KeyValueNode:
    def compose(self):
        return self._index + self._signs + ' ' + self.value + '\n'
        # 输出: "title: 翻译后的标题"

# 图片链接节点重组
class ImageOrLinkNode:
    def compose(self):
        # 复杂的重组逻辑，保持链接结构，翻译描述文本
        return f'![{translated_description}]({original_link})'
```

#### 4.3 语言特定格式优化
**负责模块**: `MarkdownTranslator.__translate_to()` 的后处理部分

**紧凑型语言处理**:
- 中文、日文等紧凑型语言：直接输出，不添加额外空格
- 英文等非紧凑型语言：在特定位置添加空格分隔

**空格添加逻辑**:
```python
# 使用正则表达式识别需要空格分隔的内容
expands_regexs = [
    r'`[^`]+?`',           # 代码片段
    r'".*?"',              # 引用内容
    r'\*\*.*?\*\*',        # 加粗文本
    r"\[!\[.*?]\(.*?\)]\(.*?\)|!?\[.*?]\(.*?\)"  # 链接
]

# 在这些内容前后适当添加空格
```

### 5. 文件输出

**最终步骤**:
- 将重组后的内容写入目标文件
- 文件命名格式：`原文件名.语言代码.md`
- 使用 UTF-8 编码确保多语言字符正确显示

## 关键技术特点

### 1. 智能内容识别
- **正则表达式驱动**: 使用精心设计的正则表达式模式识别不同类型的 Markdown 内容
- **状态机处理**: 通过状态标识准确识别 Front Matter、代码块等特殊区域
- **节点化抽象**: 将复杂的 Markdown 结构抽象为简单的节点对象

### 2. 格式保护机制
- **分离式处理**: 将格式标记与内容分离，只翻译内容部分
- **位置记忆**: 记录各部分在原文中的位置关系，翻译后精确重建
- **类型化重组**: 不同类型的内容有专门的重组逻辑

### 3. 性能优化策略
- **批量处理**: 将多个小文本合并后批量翻译，减少 API 调用次数
- **并发翻译**: 多线程同时处理不同语言的翻译任务
- **智能分块**: 根据内容长度智能分块，平衡效率和质量

### 4. 错误处理与容错
- **重试机制**: API 调用失败时自动重试，提高成功率
- **进度跟踪**: 实时显示翻译进度，支持错误状态显示
- **异常隔离**: 单个文件翻译失败不影响其他文件处理

## 配置驱动的灵活性

### Front Matter 处理配置
```yaml
# 不翻译的键
front_matter_transparent_keys:
  - 'date:'
  - 'slug:'
  
# 键值对翻译
front_matter_key_value_keys:
  - 'title:'
  - 'description:'
  
# 数组值翻译  
front_matter_key_value_array_keys:
  - 'tags:'
  - 'categories:'
```

### 语言特性配置
```yaml
# 紧凑型语言（不需要空格分隔）
compact_langs:
  - zh-TW
  - ja

# 各语言的警告信息
warnings_mapping:
  en: "Warning: This page is translated by MACHINE..."
  zh: "警告：本文由机器翻译生成..."
```

## 总结

Free Markdown Translator 的文档处理逻辑体现了以下设计原则：

1. **结构化处理**: 通过节点化抽象将复杂的 Markdown 文档结构化处理
2. **内容与格式分离**: 只翻译内容，完美保持格式
3. **配置驱动**: 通过配置文件灵活控制处理行为
4. **性能优先**: 批量处理和并发执行提高翻译效率
5. **容错设计**: 完善的错误处理和重试机制

这种设计使得工具既能准确翻译内容，又能完美保持 Markdown 文档的结构和格式，是一个在实用性和技术实现上都很优秀的解决方案。
